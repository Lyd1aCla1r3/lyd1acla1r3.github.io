Test Patterns and Jitter Isolation

Prefer to read this seamlessly offline? Download the complete, formatting-optimized Signal Integrity eBook here.

The jitter decomposition framework described in Jitter Decomposition and Measurement establishes that total jitter separates into Random Jitter and Deterministic Jitter, and that Deterministic Jitter subdivides further into Data Dependent Jitter and Periodic Jitter. The Dual-Dirac Model and BER Extrapolation provides the statistical machinery to project these components to any target BER. Both of those guides operate on the measured histogram and the extracted numerical parameters ($RJ_{\text{rms}}$, $DJ_{\delta\delta}$). Neither addresses the physical measurement techniques that produce the separation in the first place.

This guide covers the practical machinery of jitter isolation: how test patterns are selected to make specific jitter components visible and measurable, how synchronous averaging extracts Data Dependent Jitter from the raw timing data, how FFT spectral decomposition identifies Periodic Jitter sources, how DCD and ISI are separated within the DDJ measurement, and how specialized patterns target specific hardware failure modes. The techniques described here correspond directly to steps 4 through 7 of the seven-step measurement flow introduced in the Architecture section of Jitter Decomposition and Measurement.

Core Concepts

From Histogram to Timeline: The TIE Track

The TIE histogram used by the Dual-Dirac model collapses all edge crossings into a probability distribution. This representation is powerful for extracting $RJ_{\text{rms}}$ and $DJ_{\delta\delta}$ through tail fitting, but it completely destroys the chronological order of the edge crossings. Decomposing Deterministic Jitter into its sub-components requires a fundamentally different data representation.

The TIE Track is a chronological sequence of Time Interval Error values plotted continuously against time. Each data point records the timing error of a specific edge crossing in the order it was captured. The horizontal axis is time (or equivalently, bit position within the capture window), and the vertical axis is the TIE value in picoseconds. The TIE Track preserves the temporal structure that the histogram discards: which edges were early, which were late, and how the timing errors evolved over millions of consecutive bit transitions.

The TIE Track is the raw material from which synchronous averaging and FFT spectral analysis extract the individual DJ components.

Why Test Patterns Must Be Pseudo-Random

A live communication link transmits scrambled data that possesses a mathematically random distribution. The transmitted bit sequences contain a complex mix of high-frequency alternating patterns and low-frequency long bit runs that trigger different physical responses in the channel. To accurately characterize a channel's jitter behavior, the test stimulus must replicate this broadband spectral content and excite all possible Intersymbol Interference conditions.

The test pattern cannot be truly random. Synchronous averaging, the core technique for extracting Data Dependent Jitter, requires the oscilloscope to capture thousands of identical repetitions of the same pattern and average the timing error at each bit position across all repetitions. A truly random sequence never repeats, making alignment and averaging impossible.

A Pseudo-Random Bit Sequence resolves this conflict. PRBS patterns provide the complex frequency spectrum of live data while maintaining the exact, repeating mathematical structure required by the averaging algorithm.

PRBS Pattern Generation and Structure

PRBS patterns are generated by Linear Feedback Shift Registers (LFSRs). A PRBS-N pattern has a length of $2^N - 1$ bits and contains every possible N-bit sequence except the all-zeros state. The pattern repeats identically after $2^N - 1$ bits, providing the deterministic structure needed for synchronous averaging.

The maximum run length of consecutive identical bits within a PRBS-N pattern is exactly N bits. A PRBS-7 pattern contains 127 bits, and its longest run of identical bits is seven (such as 1111111). A PRBS-15 pattern contains 32,767 bits with a maximum run of fifteen. A PRBS-31 pattern contains approximately 2.1 billion bits with a maximum run of thirty-one.

The maximum run length is the critical parameter for ISI testing. Long runs of identical bits allow the channel's distributed capacitance to charge or discharge fully, establishing the maximum voltage swing. When the pattern transitions out of a long run, the signal must traverse the full voltage distance to the opposite rail, exposing the worst-case ISI condition. Longer maximum runs create more severe ISI stress.

PRBS-7: The Workhorse Pattern

PRBS-7 is the most widely used pattern in jitter characterization for two reasons.

It is short enough to allow an oscilloscope to capture tens of thousands of complete repetitions within a standard memory buffer. A 127-bit pattern repeating 10,000 times requires only 1.27 million bits of capture depth. This accumulation provides the statistical depth needed for synchronous averaging to suppress RJ and PJ by a factor of $\sqrt{N}$, where N is the number of averaged repetitions.

Its maximum run length of seven directly stresses the encoding boundaries of foundational high-speed standards. PCIe Gen 1, SATA, and Gigabit Ethernet use 8b/10b encoding, which mathematically prevents any data run longer than five identical consecutive bits. A PRBS-7 pattern with its run length of seven exceeds this limit, providing a necessary physical guardband that proves the system survives worst-case ISI conditions across all temperature variations, voltage droops, and manufacturing tolerances.

Modern standards using 128b/130b encoding (PCIe Gen 3 and beyond) permit much longer identical bit sequences. Validating these links requires PRBS-15 or PRBS-31 patterns to simulate worst-case ISI channel charging at low frequencies. The tradeoff is measurement time: a PRBS-31 pattern requires billions of bits per repetition, and accumulating thousands of repetitions for synchronous averaging demands deep oscilloscope memory and long acquisition windows.

Why PRBS-5 Is Avoided

PRBS-5 contains only 31 bits before repeating. While it does include a run length of five, a 31-bit sequence lacks the spectral density required to simulate live data. Real communication traffic contains a massive variety of transition histories and frequency combinations that excite different physical resonances in the printed circuit board traces. A repeating 31-bit loop is too simple to trigger those complex channel interactions.

The practical barrier is equally significant. The LFSR polynomial required to generate PRBS-7 is physically hardcoded into the silicon of nearly every commercial Bit Error Ratio Tester and internal SerDes test block. PRBS-5 is rarely implemented in hardware generation logic, making it impractical for standardized laboratory testing.

Worked Examples

Synchronous Averaging for DDJ Extraction

Synchronous averaging is the technique that separates Data Dependent Jitter from all uncorrelated jitter sources. The procedure exploits the defining property of DDJ: it is correlated to the bit pattern, meaning the same bit sequence produces the same timing error on every repetition.

Step 1: Acquire multiple pattern repetitions. The hardware under test transmits a repeating PRBS-7 pattern (127 bits per repetition). The oscilloscope captures thousands of repetitions of the complete pattern and measures the TIE at every edge transition.

Step 2: Align and average. The software identifies the pattern boundary and mathematically aligns every captured repetition. For each bit position within the pattern (bit 1, bit 2, through bit 127), the algorithm averages the TIE values recorded across all repetitions.

Step 3: Observe the cancellation. Random Jitter and Periodic Jitter are entirely uncorrelated to the bit sequence. At any given bit position, the RJ contribution is equally likely to be positive or negative on successive repetitions. Averaging thousands of these positive and negative swings drives their contribution toward zero. After N averages, the uncorrelated jitter amplitude reduces by a factor of $\sqrt{N}$. With 10,000 repetitions, uncorrelated jitter is suppressed by a factor of 100.

Step 4: Isolate the DDJ. The only timing error that survives the averaging process is the jitter physically caused by the data pattern itself. If bit position 47 consistently arrives 2.3 ps late (because it follows a long run of zeros and the channel's parasitic capacitance requires extra charging time), that 2.3 ps offset appears in the averaged waveform regardless of how many repetitions are captured. This isolated remainder is pure Data Dependent Jitter, encompassing both Intersymbol Interference and Duty Cycle Distortion.

DCD and ISI Separation

Once the software isolates the total DDJ track, separating DCD from ISI is a sorting operation based on edge polarity.

Duty Cycle Distortion is caused by a physical asymmetry between rising edges and falling edges. The oscilloscope software calculates the average timing error of every rising edge in the pattern and compares it to the average timing error of every falling edge. If rising edges cross the threshold consistently earlier than falling edges (as occurs when the pull-up transistor has stronger drive strength than the pull-down transistor), the software extracts that static time delta and classifies it as DCD.

After subtracting the DCD baseline, the remaining timing variations fluctuate based strictly on the historical sequence of bits leading up to each transition. This residual variance is classified entirely as Intersymbol Interference.

FFT Spectral Decomposition for Periodic Jitter

The oscilloscope takes the isolated DDJ values and subtracts them from the original, raw TIE Track. The remaining data track now contains strictly uncorrelated jitter: a mixture of Random Jitter and Periodic Jitter.

To separate them, the oscilloscope executes a Fast Fourier Transform on the remaining track, converting the timing data from the time domain into the frequency domain.

Random Jitter is broadband white noise. Its energy spreads evenly across all frequencies, creating a flat, low-level noise floor at the bottom of the FFT graph. This flat floor is the spectral signature of the Gaussian process described in Jitter Decomposition and Measurement: billions of independent microscopic thermal events producing a featureless distribution of timing perturbations.

Periodic Jitter is driven by specific oscillating sources. A 33 MHz switching power supply, a 100 MHz adjacent clock trace, or a ringing PLL each produces a sinusoidal modulation of the edge timing at its characteristic frequency. In the frequency domain, these periodic interferences appear as sharp, distinct spectral spikes rising well above the RJ noise floor.

The algorithm identifies each spike that exceeds the noise floor by a specified margin (typically 6 to 10 dB), records its frequency and amplitude, and quantifies the Periodic Jitter contribution. The frequency of each spike directly identifies the interference source, transforming an opaque timing problem into an actionable hardware diagnostic.

Architecture

Specialized Jitter Test Patterns

Standard PRBS patterns exercise the full spectral range of a channel, but specific hardware failure modes are more efficiently exposed by purpose-built patterns.

Clock Pattern (101010...): This pattern operates exclusively at the highest fundamental frequency of the link (the Nyquist rate). It contains no long consecutive bit runs, so the channel's distributed capacitance never fully charges or discharges. ISI is effectively eliminated. Engineers transmit a clock pattern to isolate and measure pure Duty Cycle Distortion or to evaluate the Random Jitter floor without channel-dependent interference. The measurement reveals only the transmitter's intrinsic timing asymmetry and the system's thermal noise baseline.

CJTPAT (Continuous Jitter Test Pattern): This pattern is designed to stress the receiver's Clock and Data Recovery circuit. It forces abrupt transitions between extremely high-frequency alternating bits and maximum-length low-frequency bit holds. The sudden shifts in frequency content challenge the CDR's Phase-Locked Loop to maintain phase lock. CJTPAT is used in receiver compliance testing to verify that the CDR can track the data under maximum stress without drifting or losing lock.

Low-Frequency Square Wave (e.g., 64 ones followed by 64 zeros): This pattern forces the transmitter to hold a static voltage state for an extended duration. It exposes power distribution network flaws by revealing vertical voltage droop that occurs when the transmitter slowly drains the local decoupling capacitors during a long sequence of identical bits. The pattern is diagnostic for supply integrity, not for timing jitter.

The Complete Measurement Flow: Steps 4 Through 7

The seven-step jitter measurement flow begins with signal acquisition, clock recovery, and TIE computation (steps 1 through 3, covered in Jitter Decomposition and Measurement). Steps 4 through 7 apply the techniques described in this guide to decompose the measured jitter into its root causes.

Step 4: Pattern Synchronization. The oscilloscope locks to the repeating test pattern to enable synchronous averaging. This requires knowledge of the pattern type and length. The software identifies pattern boundaries by correlating the captured data with the known PRBS polynomial.

Step 5: Deterministic Jitter Extraction. Synchronous averaging separates DDJ from all uncorrelated jitter. The averaged TIE Track isolates the pattern-correlated timing errors. DCD is separated from ISI by comparing rising-edge and falling-edge averages. The remaining uncorrelated jitter residual (original TIE Track minus DDJ) contains only RJ and PJ.

Step 6: Spectral Decomposition. FFT analysis of the uncorrelated residual separates Periodic Jitter (sharp spectral spikes at identifiable frequencies) from Random Jitter (flat broadband noise floor). Each PJ spike is cataloged with its frequency and amplitude.

Step 7: Statistical Validation. The decomposition is validated by confirming internal consistency. The total jitter reconstructed from decomposed components ($DJ_{\text{p-p}} + 2Q \cdot RJ_{\text{rms}}$) should match the directly measured total jitter within measurement uncertainty. The RJ histogram should be approximately Gaussian (verified by normality tests). DJ should be bounded and repeatable across successive measurements. Where the observation window is long enough to produce a measurable BER, the extrapolated BER from the Dual-Dirac model should agree with the directly counted error rate.

Edge Cases

Pattern Length vs. Averaging Depth Tradeoff

Longer PRBS patterns provide richer spectral content and exercise more ISI conditions, but they require proportionally more measurement time to achieve the same averaging depth. A PRBS-7 pattern at 10 Gbps repeats approximately 79 million times per second. Accumulating 10,000 averages takes a fraction of a millisecond. A PRBS-31 pattern at the same data rate repeats approximately 4.7 times per second. Accumulating 10,000 averages would require over 35 minutes of continuous acquisition.

The practical consequence is that PRBS-31 measurements typically use fewer averaging repetitions, which reduces the suppression of uncorrelated jitter in the DDJ extraction. The residual RJ contamination in the DDJ measurement is higher, reducing the accuracy of the decomposition. Engineers must balance the need for realistic spectral content (longer patterns) against the need for clean DDJ isolation (more averages of shorter patterns).

Measurement Floor and Instrument Noise

The oscilloscope itself contributes jitter to every measurement. Trigger jitter, sampling clock phase noise, and analog front-end noise all add to the measured TIE values. These instrument contributions set a measurement floor below which the device under test's jitter cannot be resolved.

For Random Jitter measurements, the instrument's own $RJ_{\text{rms}}$ adds in quadrature with the DUT's $RJ_{\text{rms}}$:

$$RJ_{\text{measured}} = \sqrt{RJ_{\text{DUT}}^2 + RJ_{\text{instrument}}^2}$$

If the instrument floor is 200 femtoseconds and the DUT's RJ is 1.5 picoseconds, the instrument contribution is negligible (less than 1% error). If the DUT's RJ is 300 femtoseconds, the instrument floor dominates and the measurement becomes unreliable.

CDR Bandwidth and Its Effect on Jitter Measurement

The Clock and Data Recovery bandwidth setting critically affects which jitter components are captured. The CDR acts as a high-pass filter on jitter: timing variations slower than the CDR bandwidth are tracked by the recovered clock (and therefore invisible to the TIE measurement), while variations faster than the CDR bandwidth appear as measured jitter.

A narrow CDR bandwidth tracks only very slow drift, exposing virtually all jitter components to measurement. A wide CDR bandwidth tracks moderate-frequency variations, effectively filtering out low-frequency PJ components. The CDR bandwidth must match the application's specification to produce compliance-relevant results. A measurement taken with a different CDR bandwidth than the standard requires is not comparable to the specification limit.
